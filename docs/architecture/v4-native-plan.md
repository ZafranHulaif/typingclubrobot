# v4 native plan (replaces the Python sidecar route)

Decided 2026-11-21 by the owner: "whatever makes it feel more responsive; native it is."
Supersedes §2-§5 of `M0-decision.md` (the sidecar, IPC and cross-process embedding).
The UI work (Flutter, brand, layout, plan tiles) is unchanged and reused as-is.

## Why
The old app felt slow because one Tk thread did UI + polling + webview + timers, not because
of Python's speed (typing is bound by the browser, not the language). The sidecar route kept
all of Python's baggage: two processes, pythonnet/.NET with the GIL "no callbacks" rule, a hidden
Tk pump, cross-process window reparenting (the riskiest part), and an 80 MB self-extracting exe.
One native program removes all of that.

## Shape
```
TypingBot (one Flutter Windows app)
├── Dart UI            ui/lib/src/ui/**       (done: approved design)
├── Dart engine        ui/lib/src/engine/**   (port of engine/*.py, module by module)
│     └── JS payloads  reused VERBATIM from engine/jstemplates.py + jsutil.py (~1.3k lines)
├── Dart net           ui/lib/src/net/**      (port of net/: license Ed25519, api, updater, report)
└── C++ runner plugin  ui/windows/runner/**   WebView2 host:
      - one CoreWebView2Environment per account data folder (same jars as 3.5.x)
      - windowed child HWND, in-process (first). Composition/texture hosting later
        to allow Flutter UI over the page.
      - CDP via CallDevToolsProtocolMethod + DevToolsProtocolEventReceiver,
        exposed to Dart over a MethodChannel/EventChannel (no debug port, no websocket)
      - AddScriptToExecuteOnDocumentCreated (window.open stub born with the document)
      - NewWindowRequested handled natively (OAuth popups stay in-app)
      - Windows OCR (Windows.Media.Ocr) for OCR lessons
```
Playwright surface the engine actually uses (grep, 2026-11-21): evaluate, keyboard
type/press/down/up, mouse.click, goto, reload, go_back, wait_for_selector, add_init_script,
url, frames/main_frame, locator (8 uses). All map to plain CDP calls.

## Porting order (each step = verified before the next)
| Step | What | Verified by |
|---|---|---|
| N1 | C++ WebView2 host: env per account folder, resize from Dart rect, show/hide, navigate, CDP bridge, init scripts, new-window handling | CI build + owner: page shows, Google login works in-app, account switch |
| N2 | Dart CDP "page" API over the bridge (subset above) | Unit tests with a fake bridge here; owner smoke on Windows |
| N3 | Engine port: state, typing_core (timing), levels, supervisor loop, session/login patrol, recovery, lessons (standard, games, video, intro/tutorial/holdkey/screenkey, ocr) | Port of `_test_harness.py` accuracy scenarios to Dart (must stay 100%) |
| N4 | Net port: license (Ed25519 verify + legacy HMAC key), api (browser UA), updater, bug report | Port of `_test_net.py` cases |
| N5 | Data compatibility: same `%LOCALAPPDATA%/TypingBot` files (license.dat, settings, profil-akun jars, level_map.json, posisi_level.json) so 3.5.x users keep license and logins | Owner upgrades a real 3.5.x install |
| N6 | Packaging + update path from 3.5.x (see open question) | CI artifact + owner install |
| N7 | Star targets (research thresholds, speed/typo control per plan segment) | Live edclub runs |

## Status
**N1 (code done 2026-11-22, CI green, waiting for owner test on Windows).**
- `ui/windows/runner/web_host.{h,cpp}`: in-process WebView2 host. SDK fetched by CMake from
  NuGet (static loader, no extra DLL). One container child HWND per webview above the
  FlutterView; env per data folder; popups become main-frame navigations; CDP methods +
  event subscriptions; init scripts before the first navigation. Channel `typingbot/web_host`.
- `ui/lib/src/web/web_host.dart`: Dart API (`WebHost.create` -> `WebView`: navigate, eval,
  cdp, on(event), addScript, setVisible).
- `ui/lib/src/web/js_init.dart`: generated by `ui/tool/gen_js.py` from the Python sources
  (verbatim; CI runs `--check`).
- `ui/lib/src/native/`: `NativeBackend` (same request/event protocol as the sidecar, so the UI
  is unchanged) + `AccountStore` (3.5.x files: `akun/aktif.json`, `profil-akun/<name>`,
  `wv2profile`).
- Known N1 limits: "Tambah akun" names the jar "Akun baru" (real name from the edclub profile
  still to do); session-cookie restore from `sesi_edclub.json` and cookie import for old
  cookie-only accounts are N5; a Flutter popover hides the page while open (windowed hosting).

**N2 (done 2026-11-22, CI green).** `ui/lib/src/engine/page.dart`: Playwright-like `Page` over a
tiny `CdpBridge` interface (`send(method, params, session)` + `listen(event)`), adapter
`native/view_bridge.dart` for the real WebView. Covers evaluate (Playwright semantics: function
strings are called with the arg), keyboard type/press/down/up (US layout table copied from
Playwright so edclub sees identical key events), mouse.click, goto/reload/goBack (wait for load),
waitForSelector, addInitScript, url, frames/mainFrame, locator (count, first/nth, click with
iframe offset, isVisible, innerText, boundingBox, selectOption, fill). Tests with a fake bridge:
`ui/test/engine_page_test.dart`.
- Decision: cross-origin iframes (balloon/monster games on `*.edclub.app`, video player on
  `corevideo.edclub.app`) are separate CDP targets. The only C++ change since N1: `cdp` accepts
  an optional `session` (CallDevToolsProtocolMethodForSession) and CDP events carry `session`.
  `Page` uses `Target.setAutoAttach(flatten)` to reach them. **Unverified on a real WebView2**:
  if game/video levels stall, this is the first suspect (look for frames in the `DEBUG` dump of
  bot.log).

**N3 (code done 2026-11-22, all tests green here; waiting for CI + owner run on edclub).**
`ui/lib/src/engine/`: one Dart file per Python module (`part` + extension on `Engine`, names
kept close to the Python so they can be compared side by side): `supervisor`, `typing_core`,
`levels` (+ `level_map.dart`), `rentang`, `session`, `recovery`, `jsutil`, `lessons/standard,
tutorial, games, video, holdkey, screenkey, intro, balloon` (balloon = the core-API half of
`lessons/ocr.py`). `state.dart` replaces the module globals; `clock.dart` makes every sleep
injectable (tests run instantly with a fake clock).
- JS payloads: `gen_js.py` now also writes `engine/js.dart` (every constant in
  `jstemplates.py`, key maps, the session-path regex, `_DAFTAR_JS`/`_KLIK_LANJUT_JS`, the
  balloon payloads, and `level_data.PETA`) and `engine/js_inline.dart` (JS written inline inside
  Python functions, found by a unique marker). CI `--check` covers all three files.
- Mode: the 3.5.x WebView2 path (`BROWSER_WV2` + `EMBED_BROWSER`): one page, no spare tabs, no
  redirect login probe, no browser launch/restart. Tab sweepers / tab switching are no-ops.
- OCR: behind `OcrService` (`engine/ocr.dart`), currently `NoOcr` = exactly 3.5.x without winocr
  (OCR paths skipped, core-API games still fed). TODO: Windows.Media.Ocr in the C++ runner.
- Backend: `NativeBackend` runs the engine. `bot.start` (plan segments -> LEVEL_START/END, else
  continue from account position), `bot.stop`, `bot.recover`, `levels.build_map`, `speed.set`
  (live + saved), `plan.set` with the lock (active segment + next 2 levels can't change while
  running; later segments can, and the range end follows), `log.tail`. 10 Hz snapshot mapping
  copied from `sidecar/engine_backend.py` (phase, needs_login, browser_closed, level
  num/label/url, range, plan active/done_in_active/lock_until) plus new `level.progress` (0..1
  for typing lessons, feeds the progress bar). Asks: `level.locked`, `level.next`. Speed + plan
  persist in `typingbot_settings.json`; engine log goes to `bot.log` + `log` events (friendly
  translation not ported yet, `friendly: null`). Account switch/add/logout refused while running.
- Decision: Mulai with an empty plan continues from `posisi_level.json` + 1 (the mock's
  "lanjut"); the old sidecar started at level 1 and could idle on the course page.
- Decision: on Mulai the backend focuses the webview first. Clicking the Flutter button blurs the
  page, and `USER_WATCH_JS` counts blur as "user active" (the bot would wait up to 25 s).
- Python bugs found while porting (fixed on the Dart side only; 3.5.x still has them):
  1. `_DAFTAR_JS` is a raw string with `\\d`, so the JS regex looks for a literal backslash:
     every row number reads 0, the "never go back" filter is dead and list skips can jump back
     to the first unlocked row. Proven by running the verbatim JS in node
     (`ui/test/engine_levels_test.dart`). Dart uses `daftarJsFixed`.
  2. `_record_level_map` only accepts `/lesson/` URLs but `build_level_map` and
     `_goto_level_via_daftar_isi` pass `.play` URLs, so map fixes were never saved. Dart records
     the route form.
  3. `_finish_recovery` waits for `.play` in the raw URL, which never appears on the new UI
     route (always 15 s wasted). Dart normalises first.
- Not ported (not needed in the native app): browser launch/port/profile code, hotkeys,
  `baca_progres_akun` (old start dialog), Stripe/ad tab sweepers, `_probe_tab_login`.
- Tests (`ui/test/engine_*_test.dart`, `native_engine_test.dart`; 92 in the whole suite after N4): typing
  accuracy against a fake edclub lesson (clean text with symbols/Enter/Tab, dropped keystrokes,
  site-marked mistakes -> Backspace and retype, pre-existing errors, progressive line render,
  stage not ready, STOP mid-lesson; all must end with zero wrong characters), burst timing
  (measured CDP overhead -> final rate = target wpm), supervisor transitions (login gate, lesson
  -> score -> next level, range end, return to range start, renderer dead, Stripe hijack,
  premium modal), strict list order, URL rules, level map, backend start/stop/lock/asks.

**N4 (code done 2026-11-22, tests green here; waiting for CI + owner run).** `ui/lib/src/net/`:
- `ed25519.dart`: hand-written RFC 8032 verify (BigInt + `package:crypto` sha512; `crypto` was
  already in the lockfile, now a direct dependency). Checked against RFC vectors and tokens signed
  by node's Ed25519.
- `license.dart`: same contract as 3.5.x: token `{mc, exp, sig}` over `v1|mc|exp`, `license.dat`
  one-line JSON or legacy HMAC key text, `request`/`status` calls, download param. Legacy HMAC
  needs the real secret (gitignored `_license_secret.py`): pass it at build time with
  `--dart-define=TB_LICENSE_SECRET=...`. CI reads repo secret `TB_LICENSE_SECRET` if the owner
  adds it; without it old manual keys are not recognised (online tokens are unaffected).
- `machine.dart`: machine code identical to `gui/licensing.py` (`mac` from
  UuidCreateSequential like Python's `uuid.getnode()`, `COMPUTERNAME`, system volume serial) via
  `dart:ffi` + kernel32 `LocalAlloc` (no extra package). Hash/base32 part verified against Python
  output; the Windows FFI part is **unverified until the owner runs it**.
- Decision: if a valid local token carries a different `mc` than v4 computes, the backend asks
  the server with the token's `mc` (and logs the mismatch) instead of showing "dicabut". Protects
  3.5.x users if the fingerprint ever differs; server contract unchanged.
- `api.dart`: `TYPINGBOT_SERVER_URL` / `server_url.txt` / default URL (same order as 3.5.x),
  browser-like UA `Mozilla/5.0 (Windows NT 10.0; Win64; x64) TypingBot/<ver> (+github...)`,
  JSON calls, streamed download with sha256.
- `updater.dart`: `parse_version`/`is_newer`/check. Download + install wait for N6 (v4 is a
  folder; `update.download`/`install` answer a friendly "menyusul").
- `report.dart`: `/api/lapor {versi, akun, isi}` with the same report text; failure saves the
  report to the Desktop.
- Backend: boot does the fast local check first (valid token = `ok` at once), then the 3.5.x
  online flow (`_net_boot`): token -> status, legacy key -> request token in background, new
  machine -> need/pending with 5 s polling up to 30 min, quick status gate before Mulai.
  New license state `checking` shows "Memeriksa lisensi..." in the existing banner.
- Tests: `ui/test/net_test.dart`, `ui/test/native_license_test.dart` (local fake worker).

### First owner test (dev3) -> fixes in dev4
Owner ran dev3 on Windows. Typing works (slow first start). Fixed in dev4:
- **Page slot drift / black area**: the webview rect was only reported on rebuild, so animated
  layout left it stale. Now `widgets/web_layer.dart` reports the slot every frame it changes.
- **Popups & plan panel over the page**: no more hiding the whole webview. Flutter sends "holes"
  (`setHoles`, physical px, rounded) and the runner cuts them out of the webview container with
  `SetWindowRgn`, so the live page stays visible around popups. The plan panel now slides OVER
  the page (no pushing). Unverified on hardware: that the WebView2 child HWND is clipped by the
  container region (should be; fallback = region on the child too).
- **Runner**: real app icon (docs/logo.ico), starts maximized, dark title bar #0B0C10, WebView2
  profile forced to light scheme (Google login page was dark).
- **Not logged in on open**: a login check runs before the cover drops; logged out = straight to
  /signin instead of the empty lesson list.
- **Two start modes** (owner request): top **Mulai** = no plan: waits for login, then waits for
  the user to open a level on the page and types from there onward. Star target for this mode is
  a picker in the capsule (stored, enforced in N7). **Mulai rencana** (button in the plan panel)
  = follow the plan. Waiting for login no longer starts the engine (no "Mengetik/Perlu login"
  flicker).
- **Paused state**: leaving the lesson while typing now shows "Dijeda" with a **Lanjut** button
  (goes back to the level in progress); opening another level on the page also continues there.
- **Plan editor**: Tambah opens a draft (saved only on "Buat"), the editor opens right under the
  tapped tile, levels capped at 685.
- Open: Google login needed two tries the first time. Likely cause (Fable review): `noPopupJs`
  turns the OAuth popup into a main-frame navigation, and edclub's callback page expects
  `window.opener`. Needs the dev4 bot.log to confirm before changing the OAuth path.

## Owner test checklist (Windows, build 4.0.0-dev6 from the CI artifact)
Close any running 3.5.x first (same data folder). Everything happens inside the app window.
1. **N1 page**: app opens, edclub shows with no white flash, Google login works inside the app,
   account switch (menu) opens the other account's edclub, logout lands on /signin.
2. **License (N4)**: with the 3.5.x `license.dat` the bar should NOT ask for a nickname. If it says
   "dicabut", copy the `[LISENSI]` lines from `%LOCALAPPDATA%/TypingBot/bot.log`.
3. **Mulai/Stop (N3)**: with a plan (e.g. 1 tile around the next level), press Mulai: the bot opens
   the level, types it, presses through the score screen, moves on. Level number and progress
   bar update in the capsule. Stop ends within a few seconds.
4. **Accuracy**: a few standard lessons should finish with 100% accuracy at 400 wpm.
5. **Lesson kinds**: try at least one each of video, intro ("type the f key"), a game (balloon /
   monster) and a tutorial. Game and video levels are the risky ones (cross-origin iframes, see
   N2 note). If one stalls >30 s, send a bug report from the app (it attaches the log).
6. **Plan lock**: while running, editing the active tile or the next one is refused with a
   friendly message; a later tile can still be changed.
7. **Speed**: changing speed while running takes effect on the next burst.
8. **Bug report** button sends (owner thread receives it).

## Python's role now
`engine/`, `net/`, `gui/` stay in the repo as the **specification** and for 3.5.x hotfixes.
`sidecar/` is parked (its mock stays useful for UI work on Linux). Nothing in Python is deleted
until v4 reaches feature parity.
