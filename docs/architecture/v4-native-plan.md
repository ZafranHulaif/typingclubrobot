# v4 native plan (replaces the Python sidecar route)

Decided 2026-11-21 by the owner: "whatever makes it feel more responsive; native it is."
Supersedes §2-§5 of `M0-decision.md` (the sidecar, IPC and cross-process embedding).
The UI work (Flutter, brand, layout, plan tiles) is unchanged and reused as-is.

## Why
The old app felt slow because one Tk thread did UI + polling + webview + timers, not because
of Python's speed (typing is bound by the browser, not the language). The sidecar route kept
all of Python's baggage: two processes, pythonnet/.NET with the GIL "no callbacks" rule, a hidden
Tk pump, cross-process window reparenting (the riskiest part), and an 80 MB self-extracting exe.
One native program removes all of that.

## Shape
```
TypingBot (one Flutter Windows app)
├── Dart UI            ui/lib/src/ui/**       (done: approved design)
├── Dart engine        ui/lib/src/engine/**   (port of engine/*.py, module by module)
│     └── JS payloads  reused VERBATIM from engine/jstemplates.py + jsutil.py (~1.3k lines)
├── Dart net           ui/lib/src/net/**      (port of net/: license Ed25519, api, updater, report)
└── C++ runner plugin  ui/windows/runner/**   WebView2 host:
      - one CoreWebView2Environment per account data folder (same jars as 3.5.x)
      - windowed child HWND, in-process (first). Composition/texture hosting later
        to allow Flutter UI over the page.
      - CDP via CallDevToolsProtocolMethod + DevToolsProtocolEventReceiver,
        exposed to Dart over a MethodChannel/EventChannel (no debug port, no websocket)
      - AddScriptToExecuteOnDocumentCreated (window.open stub born with the document)
      - NewWindowRequested handled natively (OAuth popups stay in-app)
      - Windows OCR (Windows.Media.Ocr) for OCR lessons
```
Playwright surface the engine actually uses (grep, 2026-11-21): evaluate, keyboard
type/press/down/up, mouse.click, goto, reload, go_back, wait_for_selector, add_init_script,
url, frames/main_frame, locator (8 uses). All map to plain CDP calls.

     the route form.

     route (always 15 s wasted). Dart normalises first.

- Tests (`ui/test/engine_*_test.dart`, `native_engine_test.dart`; 92 in the whole suite after N4): typing

**N4 (code done 2026-11-22, tests green here; waiting for CI + owner run).** `ui/lib/src/net/`:
- `ed25519.dart`: hand-written RFC 8032 verify (BigInt + `package:crypto` sha512; `crypto` was
  already in the lockfile, now a direct dependency). Checked against RFC vectors and tokens signed
  by node's Ed25519.
- `license.dart`: same contract as 3.5.x: token `{mc, exp, sig}` over `v1|mc|exp`, `license.dat`
  one-line JSON or legacy HMAC key text, `request`/`status` calls, download param. Legacy HMAC
  needs the real secret (gitignored `_license_secret.py`): pass it at build time with
  `--dart-define=TB_LICENSE_SECRET=...`. CI reads repo secret `TB_LICENSE_SECRET` if the owner
  adds it; without it old manual keys are not recognised (online tokens are unaffected).
- `machine.dart`: machine code identical to `gui/licensing.py` (`mac` from
  UuidCreateSequential like Python's `uuid.getnode()`, `COMPUTERNAME`, system volume serial) via
  `dart:ffi` + kernel32 `LocalAlloc` (no extra package). Hash/base32 part verified against Python
  output; the Windows FFI part is **unverified until the owner runs it**.
- Decision: if a valid local token carries a different `mc` than v4 computes, the backend asks
  the server with the token's `mc` (and logs the mismatch) instead of showing "dicabut". Protects
  3.5.x users if the fingerprint ever differs; server contract unchanged.
- `api.dart`: `TYPINGBOT_SERVER_URL` / `server_url.txt` / default URL (same order as 3.5.x),
  browser-like UA `Mozilla/5.0 (Windows NT 10.0; Win64; x64) TypingBot/<ver> (+github...)`,
  JSON calls, streamed download with sha256.
- `updater.dart`: `parse_version`/`is_newer`/check. Download + install wait for N6 (v4 is a
  folder; `update.download`/`install` answer a friendly "menyusul").
- `report.dart`: `/api/lapor {versi, akun, isi}` with the same report text; failure saves the
  report to the Desktop.
- Backend: boot does the fast local check first (valid token = `ok` at once), then the 3.5.x
  online flow (`_net_boot`): token -> status, legacy key -> request token in background, new
  machine -> need/pending with 5 s polling up to 30 min, quick status gate before Mulai.
  New license state `checking` shows "Memeriksa lisensi..." in the existing banner.
- Tests: `ui/test/net_test.dart`, `ui/test/native_license_test.dart` (local fake worker).

itself, never under %LOCALAPPDATA%/TypingBot; locked (running) files are skipped. CI checks it.

### dev17: why the 3.5.x swap fails for some users
`net/updater.py` writes `set EXE="%~dp0<name>"` (value already quoted) and then `ren "%EXE%" ...`,
so the path ends up double-quoted (`""C:\...""`) = effectively unquoted. Any space in the exe name
(browser duplicate "TypingBot (1).exe") or in the path (Windows username with a space) breaks the
ren 90 times, the script rolls back and relaunches the old exe; the next download is then named
`<name>.new.exe`, which is how the `.new.exe.new.exe` chains appear. v4 cannot fix the old script,
but the downloaded bundle runs under any name: running that `.new.exe` once (or downloading
TypingBot.exe from the release) installs v4. The launcher then deletes the old copies and, when
it deleted any, writes a Desktop `TypingBot.lnk` to the installed app (old desktop links pointed at
the deleted copies). v4's own updater never uses that script.
dev18: users with a broken swapper download TypingBot.exe from GitHub (any folder). On install the
launcher reads the old Start Menu `TypingBot.lnk` target (3.5.x points it at the exe the user ran)
BEFORE repointing it, and cleans that folder too (CI covers it).

### dev20: menus while the bot runs
Closing a popover while running called web.refocus -> native GotFocus -> every popover's
"page clicked" listener closed itself, including one just opened by the same click. Now
`WebView.focus()` stamps `WebHost.selfFocusAt` and focus events within 900 ms are ignored;
refocus waits 150 ms and only fires when no popover is open. Embedded popovers close instantly
(fading out over the webview hole showed an empty dark hole, worse while the bot is busy).

### dev21: app gets focus when started from TypingBot.exe
Windows foreground lock: the launcher calls AllowSetForegroundWindow(app pid), keeps its splash
until the app's top-level window is visible (max 20 s), then SetForegroundWindow on it; the
runner also calls SetForegroundWindow after ShowWindow.

### dev22: games follow the star target (Fable, verified live)
Speed-only pacing was unsafe because each game's danger scales with goal_wpm (balloon sink speed
0.3*goal, monster push-back 350/goal, TempleBash 2 s + 12/goal per letter). New approach: type at a
safe pace `wpm = ceil(goal * max(1.25, target/0.88))` (integer, >= goal, off above 150 wpm) with real
delays, and steer the ratio with single deliberate first-try misses (block mode: a miss does not
advance, accuracy stays 100, only real_accuracy drops), closed-loop on the scoring core's live
stats (GAME_STAT_JS) before every letter, aiming at the band centre. MonsterAttack ends when the
monster is pushed off (~50-60% of text); real accuracy counts spaces it skips (explains the old
mismatch). 15 live runs (Balloon 2953/2937/2938, Monster 2941, targets 1-5) all landed on target.
Enabled: BalloonValley, MonsterAttack. TempleBash and FloatingBubbles stay full speed (premium
on the test account, untested). Unverified: Dart engine end to end on Windows, goals other than 10.
